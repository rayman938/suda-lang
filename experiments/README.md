# سجل القياسات

لا تكتب نتائج متوقعة أو تولّدها من مواصفة اللغة. شغّل الأداة على الجهاز
المقصود، واحتفظ بالناتج كما طُبع مع إعداداته:

```powershell
python benchmarks\benchmark.py --items 1000 --rounds 15 --warmup 3 > experiments\latest-benchmark.json
```

يجب تسجيل الجهاز ونظام التشغيل وحالة الطاقة والحرارة ومصدر الملف والالتزام
الذي قِيست عليه النتائج. JSON الناتج يسجل إصدار Python، النظام، حجم الإدخال،
الإحماء، التكرارات، زمن الترجمة منفصلًا عن زمن التنفيذ، وتقدير
`tracemalloc`. كما يقيس الإصدار الحالي حجم bytecode قبل ضغط zlib وبعده
وزمن الضغط وفكّه للبرنامج محل الاختبار. هذه القياسات خاصة بذلك البرنامج،
وضغط bytecode لا يقيس ضغط نماذج AI. تقدير `tracemalloc` ليس ذروة RAM للعملية
ولا قياسًا للطاقة.

يحتفظ `002-zlib-bytecode.md` بعينة صغيرة لتجربة الضغط. لا تعمم نسبتها أو
أزمنتها على برامج أخرى؛ أعد تشغيل الأداة على الملف وحجم البيانات المستهدفين.

لتتبع التجارب التاريخية، انسخ القالب التالي إلى ملف جديد باسم فريد. لا
تستبدل ملف تجربة سابقة ولا تحذف فشلًا:

```text
## تجربة <معرّف فريد>
- التاريخ والوقت والمنطقة الزمنية:
- الالتزام/نسخة المصدر:
- الجهاز والمعالج والذاكرة:
- نظام التشغيل ونسخة Python:
- أمر التنفيذ:
- حجم الإدخال والتكرارات والإحماء:
- حالة الطاقة والحرارة:
- الفرضية:
- خط الأساس:
- النتيجة الخام (مسار JSON):
- الجودة/صحة الناتج:
- ذروة RAM المقاسة بأداة نظام مستقلة:
- الطاقة المقاسة ومصدر القياس:
- التفسير والقيود:
- قرار التجربة التالية:
```

لا تقارن أرقامًا تم جمعها بخوارزميات أو إعدادات مختلفة وكأنها قياس أداء
للغة وحدها. أداة المقارنة الحالية تستخدم حلقة جمع واحدة في VM سُدى وفي
Python، وتتحقق من النتيجة، لكنها لا تمثل أحمال التطبيقات الحقيقية.
