## 1. ما سُدى؟

سُدى لغة صغيرة ذات كتابة عربية أولًا، صُممت لتجربة سلسلة تنفيذ واضحة:

```text
ملف UTF-8
   ↓
المحلل المعجمي (lexer)
   ↓
المحلل النحوي (parser)
   ↓
شجرة تعليمات (AST)
   ↓
مولّد bytecode
   ↓
الآلة الافتراضية (VM)
```

تتعمّد النواة ألّا تمنح البرنامج إمكان استيراد وحدات Python أو استدعاء
الدوال الداخلية الاعتباطية. مجموعة القدرات محدودة ومعلنة؛ لا توجد تعليمات
قراءة ملفات أو شبكة أو تشغيل أوامر نظام في المكتبة القياسية الحالية.

## 2. ما يلزم لتشغيلها؟

- Python 3.11 أو أحدث.
- ملفات المصدر محفوظة بترميز UTF-8.
- لا حاجة إلى تنزيل نماذج أو الاتصال بالإنترنت.
- لا توجد مكتبات طرف ثالث أثناء التشغيل.

تحقق من نسخة Python:

```powershell
python --version
```

ثبت المشروع في وضع التطوير:

```powershell
python -m pip install -e .
```

أو شغله من مجلد المشروع من دون تثبيت:

```powershell
$env:PYTHONPATH = "src"
python -m suda --version
```

## 3. أول برنامج

احفظ النص التالي في `hello.sada`:

```text
اسم = "سُدى"
اطبع("أهلًا بك في", اسم)
```

ثم شغله:

```powershell
suda run hello.sada
```

الناتج المتوقع:

```text
أهلًا بك في سُدى
```

التعليقات تبدأ بعلامة `#` وتستمر حتى نهاية السطر:

```text
# هذه ملاحظة لا ينفذها البرنامج
اطبع("مرحبا")
```

كل ملف يجب أن يكون UTF-8. تستخدم الكتل أربع مسافات موصى بها. لا تخلط
المسافات بعلامات tab في المسافة البادئة للكتل؛ يرفضها المحلل المعجمي مع رقم
السطر. يمكن تنسيق التعبيرات داخل الأقواس على عدة أسطر دون إنشاء كتلة:

```text
قيم = [
    3,
    5,
    8,
]
```

يجب أن تتطابق الأقواس `()`, `[]`, `{}`؛ يوضح الخطأ مكان القوس الافتتاحي أو
الإغلاق غير المطابق.

## 4. واجهة الأوامر

### 4.1 فحص المصدر

```powershell
suda check examples/حساب.sada
```

يفحص الأمر أن النص يمر من التحليل والتوليد، لكنه لا ينفذ البرنامج، لذلك
قد لا يكشف أخطاء وقت التشغيل مثل القسمة على صفر أو الاسم الذي لا يُعرّف إلا
في فرع لم يُنفذ.

### 4.2 تشغيل المصدر

```powershell
suda run examples/حساب.sada
suda run examples/حساب.sada --max-steps 200000
suda run examples/حساب.sada --max-depth 64
```

- `--max-steps`: الحد الأقصى للتعليمات التي تنفذها الآلة في العملية كلها.
- `--max-depth`: عمق الاستدعاء المتداخل للدوال.

يجب أن تكون القيم أعدادًا صحيحة موجبة، وعمق الاستدعاء لا يتجاوز 128 إطارًا
لحماية مكدس Python المضيف. عند نفاد حد الخطوات، يوقف البرنامج
وتظهر رسالة تشخيصية بدل تعليق مستمر.

### 4.3 حفظ bytecode

```powershell
suda compile examples/حساب.sada -o build/حساب.sbc
```

الامتداد `.sbc` اصطلاح تنظيمي. يكون المحتوى افتراضيًا JSON مختصرًا بترميز
UTF-8. يمكن استخدام `--compress` لتخزينه بصيغة ثنائية مضغوطة بـzlib:

```powershell
suda compile examples/حساب.sada -o build/حساب.sbc --compress
```

يقرأ المشغل الصيغتين تلقائيًا، لذا لا يتغير أمر `run-bytecode`. الضغط يقلل
حجم التخزين والنقل مقابل وقت إضافي للضغط وفكّه؛ لا يسرع تنفيذ البرنامج بعد
تحميله، وقد يكون أثره صغيرًا في الملفات القصيرة. اختبر حجم ملفاتك قبل تفعيله
في سير عملك.

### 4.4 تفكيك التعليمات

```powershell
suda disassemble build/حساب.sbc
```

يعرض الأمر أسماء الدوال والتعليمات وأرقام أسطر المصدر؛ وهو أداة تشخيصية
لفهم ناتج المترجم، لا جزء من نحو اللغة.

### 4.5 تشغيل bytecode

```powershell
suda run-bytecode build/حساب.sbc
```

اعتبر ملفات bytecode الخارجية مدخلات غير موثوقة حتى إضافة تحقق توقيع وسياسة
قدرات؛ وجود قائمة تعليمات محددة لا يغني وحده عن تدقيق أمان التنسيق كاملًا.

## 5. الترميز والرموز والمعرّفات

### 5.1 الترميز

يقرأ CLI المصدر بترميز UTF-8 فقط. أسماء المتغيرات والدوال يمكن أن تكون عربية
أو إنجليزية. لا توجد حساسية لحالة الأحرف في العربية، لكن الإنجليزية حساسة
لحالة الأحرف لأنها معرّفات Unicode عادية.

### 5.2 المعرّفات

أمثلة صحيحة:

```text
الاسم
مجموع_الطلب
احسب_المتوسط
item_count
س
```

يبدأ المعرّف بحرف Unicode أو شرطة سفلية، ويمكن أن يحتوي لاحقًا على أرقام.
المسافة ليست جزءًا من الاسم. لا يزيل الإصدار الحالي التشكيل أو التطويل
تلقائيًا؛ اكتب الاسم نفسه في التعريف والاستخدام.

### 5.3 علامات الترقيم والعوامل

العوامل المتاحة:

```text
+  -  *  /  //  %  **
==  !=  <  <=  >  >=
```

والعلامات:

```text
( ) [ ] , : .
```

النقطة متاحة معجميًا فقط، لكن الوصول إلى خصائص الكائنات ليس ميزة منفذة.
لا يمكن كتابة `شيء.حقل` في برنامج عامل بعد، وتظهر رسالة خطأ نحوي مناسبة.

## 6. القيم والأنواع الديناميكية

القيم المدعومة الآن:

| الشكل | المعنى | مثال |
|---|---|---|
| عدد صحيح | عدد صحيح بدقة Python مع حد 4096 بت للنتيجة الحسابية | `42` |
| عدد عشري | عدد عائم ثنائي | `3.14` |
| نص | سلسلة Unicode بين اقتباسين مزدوجين | `"لغة عربية"` |
| منطقي | قيمة منطقية | `صحيح`، `خطأ` |
| لا شيء | غياب قيمة | `لا_شيء` |
| قائمة | قائمة مرتبة قابلة للفهرسة | `[3, 5, 8]` |
| قاموس | أزواج مفتاح/قيمة مرتبة | `{"اسم": "سُدى"}` |

النظام ديناميكي في الإصدار الأول؛ لا يوجد فاحص أنواع ساكن أو تصريح نوع
إلزامي. العمليات التي لا تتوافق أنواعها تعطي تشخيصًا وقت التشغيل مع رقم
السطر.

### 6.1 المنطق والقيم الفارغة

```text
متصل = صحيح
مكتمل = خطأ
نتيجة_اختيارية = لا_شيء
```

عامل النفي هو `ليس`. وتُفسر القيم في الشرط وفق قواعد truthiness الخاصة
بـ Python للآلة الحالية؛ هذه نقطة مؤقتة ينبغي تثبيتها بمواصفة مستقلة قبل
الوعد بالتوافق بين أهداف تنفيذ مختلفة.

### 6.2 النصوص

السلاسل تستخدم اقتباسًا مزدوجًا، وتهريب JSON القياسي، مثل:

```text
سطران = "الأول\nالثاني"
اقتباس = "قال: \"أهلًا\""
```

لا يقبل المحلل السلسلة متعددة الأسطر داخل الاقتباس حاليًا. يمكن ضم النصوص
بعامل `+` إذا كان الطرفان نصين:

```text
التحية = "أهلًا " + "بالعالم"
```

## 7. المتغيرات والثوابت

### 7.1 إسناد متغير

```text
عداد = 0
عداد = عداد + 1
```

الاسم يُنشأ عند أول إسناد. الدوال ترى متغيرات النطاق العام التي أُنشئت قبل
وقت استعمالها، لكن الإسناد داخل الدالة ينشئ متغيرًا محليًا. لا توجد كلمة
`global` أو إغلاق closures بعد.

### 7.2 الثابت

```text
ثابت الحد_الأقصى = 100
```

يحظر إعادة إسناد الاسم نفسه في النطاق الذي عُرّف فيه الثابت. الثبات سطحي:
القائمة أو القاموس المسند إلى ثابت لا يمكن إعادة إسناد اسم الثابت، لكن يمكن
تعديل عناصر الكائن القابل للتغيير عبر الفهرسة، كما في Python.

## 8. التعبيرات وأسبقية العوامل

من الأقل إلى الأعلى:

| الأسبقية | العامل |
|---:|---|
| 1 | `أو` |
| 2 | `و` |
| 3 | `== != < <= > >=` |
| 4 | `+ -` |
| 5 | `* / // %` |
| 6 | `**` |
| 7 | العامل الأحادي `+ - ليس` |

مثال:

```text
الناتج = 2 + 3 * 4
اطبع(الناتج) # 14
```

الأقواس توضح ترتيب الحساب:

```text
الناتج = (2 + 3) * 4
```

الأس `**` يتجمع من اليمين. العوامل `و` و`أو` قصيرة الدائرة: إذا حسمت
النتيجة من الطرف الأيسر لا يحسب الطرف الأيمن.

```text
اطبع(خطأ و (1 / 0)) # يطبع False دون قسمة
اطبع(صحيح أو (1 / 0)) # يطبع True دون قسمة
```

المقارنات المتسلسلة مثل `1 < س < 9` ليست مدعومة؛ اكتبها `1 < س و س < 9`.

## 9. القوائم والقواميس والفهرسة

```text
قيم = [10, 20, 30]
اطبع(قيم[0])
اطبع(قيم[-1])
اطبع(طول(قيم))
```

القواميس تستخدم الأقواس المعقوفة، وتقبل المفاتيح القابلة للتجزئة:

```text
مستخدم = {"الاسم": "ليلى", "العمر": 30}
اطبع(مستخدم["الاسم"])
مستخدم["العمر"] = مستخدم["العمر"] + 1
```

المفاتيح المكررة في literal تستبدل قيمتها بالقيمة الأخيرة، وفق سلوك قاموس
Python. القوائم والقواميس mutable وتقبل إسناد العناصر:

```text
قيم = [10, 20]
قيم[0] = 99
```

وتتوفر دوال مساعدة للمجموعات:

```text
أضف(قيم, 30)
اطبع(مفاتيح(مستخدم))
اطبع(قيم(مستخدم))
اطبع(عناصر(مستخدم))
العمر_السابق = احذف(مستخدم, "العمر")
```

`أضف` تعدّل القائمة المحددة ولا تتجاوز حد العناصر. `احذف` يحذف مفتاح قاموس
موجود ويعيد قيمته، ويصدر خطأ إن لم يوجد المفتاح. دوال `مفاتيح` و`قيم`
و`عناصر` تنشئ قوائم جديدة مرتبة بترتيب الإدراج.

لا يمكن إسناد فهرس إلى سلسلة أو `range`. المفاتيح غير القابلة للتجزئة،
والفهرس الخارج عن حدود قائمة، ينتجان خطأ وقت تشغيل مع رقم السطر. القواميس
والقوائم المتداخلة مدعومة، بما في ذلك المراجع الدائرية؛ طباعة مرجع دائري
تعرض `[...]` أو `{...}` بدل التكرار إلى ما لا نهاية.

الفهرسة تستخدم دلالات Python للقوائم والسلاسل: يبدأ الفهرس من صفر، والفهرس
السالب يعدّ من النهاية. الفهرس خارج الحدود ينتج خطأ وقت تشغيل محدد السطر.
التقطيع `قائمة[بداية:نهاية]` غير مدعوم في الإصدار الحالي. يفحص حد المجموعات
القوائم والقواميس التي تُنشأ أثناء التنفيذ، ولا يجعل استهلاك Python الكلي
حدًا صارمًا للذاكرة.

القوائم والقواميس والمكدس محدودة افتراضيًا إلى 100,000 عنصر؛ حجم ملف المصدر
1 MiB. هذه حدود عناصر وليست حدًا مضمونًا لاستهلاك RAM بالبايت؛ حمل Python
والمراجع والكائنات غير محسوب بدقة. يمكن تعديل الحد عند استخدام VM برمجيًا،
ولا يتيح CLI تغييره حاليًا.

## 10. الشروط والكتل

```text
إذا العمر >= 18:
    اطبع("بالغ")
وإلا:
    اطبع("قاصر")
```

يمكن تداخل الشروط، وتقبل صيغة `وإلا إذا`:

```text
إذا الدرجة >= 90:
    اطبع("ممتاز")
وإلا إذا الدرجة >= 60:
    اطبع("ناجح")
وإلا:
    اطبع("أعد المحاولة")
```

يحدد النقطتان `:` بداية كتلة ذات مسافة بادئة. يجب أن تستخدم الكتلة زيادة
ثابتة في المسافة وأن تعود إلى مستوى سابق. لا توجد أقواس كتلية أو فواصل
منقوطة في الإصدار الحالي.

## 11. الحلقات

### 11.1 حلقة طالما

```text
عداد = 0
طالما عداد < 3:
    اطبع(عداد)
    عداد = عداد + 1
```

تستمر الحلقة طالما الشرط صحيح. يمكن إنهاؤها بـ `اكسر` أو تخطي التكرار
الحالي بـ `استمر`. حد التعليمات يمنع حلقة لا نهائية من العمل بلا حد.

### 11.2 حلقة لكل

```text
لكل عنصر في [2, 4, 6]:
    اطبع(عنصر)
```

يمكن الدوران على قائمة أو نص أو قيمة قابلة للتكرار يوفرها builtin. `مدى`
ينشئ range شبيهًا بنطاق Python ويقبل وسيطًا أو اثنين أو ثلاثة:

```text
لكل عدد في مدى(5):
    اطبع(عدد)

لكل عدد في مدى(2, 8, 2):
    اطبع(عدد)
```

يفشل `مدى` إذا تجاوز عدد عناصره حد المجموعة المحدد للآلة.

### 11.3 الخروج من الحلقة ومتابعتها

```text
لكل عدد في مدى(10):
    إذا عدد == 2:
        استمر
    إذا عدد == 7:
        اكسر
    اطبع(عدد)
```

`اكسر` ينهي أقرب حلقة تحيط به، و`استمر` ينتقل إلى التكرار التالي لأقرب
حلقة. يمكن تداخلهما في الحلقات والشروط؛ استعمالهما خارج الحلقات خطأ ترجمة.

## 12. الدوال

### 12.1 تعريف واستدعاء

```text
دالة اجمع(أ, ب):
    أرجع أ + ب

نتيجة = اجمع(7, 8)
اطبع(نتيجة)
```

الدالة تعيد `لا_شيء` تلقائيًا إذا وصلت إلى آخر جسمها دون `أرجع`.
`أرجع` خارج الدالة خطأ ترجمة. عدد الوسائط يُتحقق منه وقت الاستدعاء.

### 12.2 النطاق

- الوسائط محلية للدالة.
- كل إسناد في جسم الدالة محلي لها.
- الاسم الذي لم يوجد محليًا يبحث عنه VM في النطاق العام ثم المكتبة.
- لا توجد نطاقات متداخلة أو closures أو معاملات افتراضية.
- تعريف الدوال يجب أن يكون في المستوى الأعلى، وليس داخل دالة أو حلقة.

### 12.3 العودية

يمكن للدالة استدعاء نفسها. يمنع حد الاستدعاء تجاوز القيمة الافتراضية 128.
استخدم `--max-depth` لتغييرها وفق حمل موثوق، ولا ترفعها بلا حاجة.

## 13. المكتبة القياسية الحالية

| الاسم العربي | الاستخدام | ملاحظة |
|---|---|---|
| `اطبع(...)` | طباعة القيم في سطر واحد | يفصل الوسائط بمسافة |
| `اطبع_سطر(...)` | مثل `اطبع` | alias |
| `طول(قيمة)` | طول سلسلة أو قائمة | يخضع لنوع القيمة |
| `مدى(نهاية)` | إنشاء مجال من صفر إلى النهاية | حد المجموعة يطبق |
| `مدى(بداية، نهاية، خطوة)` | مجال تكراري | لا يسمح بخطوة صفر |
| `نطاق(...)` | alias عربي للمدى | يقبل نفس الوسائط |
| `نص(قيمة)` | تحويل إلى نص | دلالات Python |
| `عدد(قيمة)` | تحويل إلى عدد صحيح | دلالات Python |
| `عائم(قيمة)` | تحويل إلى عدد عائم | دلالات Python |
| `نوع(قيمة)` | اسم نوع التنفيذ | اسم داخلي لا عقد توافق دائم |
| `أقصى(...)` | أكبر قيمة | دلالات builtin |
| `أدنى(...)` | أصغر قيمة | دلالات builtin |
| `مجموع(قابل_للتكرار)` | مجموع العناصر | قد يفشل عند الأنواع غير المتوافقة |
| `اجمع(...)` | alias للمجموع | يستقبل iterable واحدًا |
| `رتب(قابل_للتكرار)` | قائمة جديدة مرتبة تصاعديًا | فرز Python المستقر؛ حد المجموعة مطبق |
| `اعكس(قابل_للتكرار)` | قائمة جديدة بترتيب معكوس | لا تغيّر القيمة الأصلية |
| `أضف(قائمة، قيمة)` | إضافة عنصر إلى نهاية قائمة | يفشل عند بلوغ حد العناصر |
| `مفاتيح(قاموس)` | قائمة المفاتيح | تحفظ ترتيب الإدراج |
| `قيم(قاموس)` | قائمة القيم | تحفظ ترتيب الإدراج |
| `عناصر(قاموس)` | قائمة أزواج `[مفتاح، قيمة]` | تنشئ قائمة جديدة |
| `احذف(قاموس، مفتاح)` | حذف المفتاح وإرجاع قيمته | يخطئ إذا لم يوجد |

لا توجد دوال شبكة أو ملفات أو shell أو AI. إضافة هذه الصلاحيات تتطلب تصميم
قدرات وموافقة واضحة، واختبارات عزل، ولا يجوز تنفيذها ضمن تقييم النصوص.

## 14. أخطاء الترجمة والتنفيذ

المترجم والآلة يرميان `SudaError` للأخطاء المتوقعة بدل تحويل الفشل إلى نجاح.
الرسائل تتضمن رقم السطر، وقد تتضمن العمود في أخطاء التحليل المعجمي والنحوي.

أمثلة:

```text
خطأ: السطر 3:5: رمز غير معروف: '$'.
خطأ: السطر 4:1: المسافة البادئة لا تطابق مستوى كتلة سابقًا.
خطأ: السطر 8:1: اسم غير معرّف: «مجموع».
خطأ: السطر 9:1: القسمة على صفر غير مسموحة.
```

قد تظهر رسالة عملية داخلية باللغة الإنجليزية إذا أتت من عملية Python لم
تُترجم بعد. عند التبليغ عن عطل، أرفق الملف المصغر وخطأه ونسخة Python.

## 15. نموذج bytecode

### 15.1 تنسيق JSON القابل للقراءة

يتاح JSON دائمًا للتشخيص، وتكون صيغة `compile` الافتراضية متوافقة مع
الإصدارات السابقة. يحمل JSON الحقول:

```json
{
  "format": "suda-bytecode",
  "version": 1,
  "entry": 0,
  "functions": [
    {
      "name": "<الرئيسية>",
      "parameters": [],
      "instructions": [
        ["CONSTANT", "مرحبا", 1],
        ["CALL", 1, 1],
        ["POP", null, 1],
        ["CONSTANT", null, 1],
        ["RETURN", null, 1]
      ]
    }
  ]
}
```

الأرقام في آخر كل تعليمة تربط bytecode بالسطر الأصلي. لا تعتمد على JSON
كصيغة تخزين دائمة قبل تثبيت قيود الطول والتوقيع والتحقق من كل معامل.

### 15.2 الحاوية الثنائية المضغوطة

استخدم `suda compile ... --compress` لإنتاج حاوية تبدأ بالبايتات الثابتة
`SUDA 00 Z1` ثم دفق zlib لمحتوى JSON نفسه. تشير العلامة إلى أن الحاوية
مضغوطة بـzlib؛ إصدار مخطط البرنامج الداخلي يبقى `1`، ولا تتغير دلالات
التعليمات. هذه حاوية ضغط وليست تنسيق bytecode أصليًا مستقلًا عن JSON.

يعتمد فك الضغط على `zlib` القياسي المرفق مع Python، بضغط المستوى `9`.
يرفض القارئ الملفات الأكبر من 16 MB بعد فك الضغط، والدفق غير المكتمل أو
ذو البيانات الزائدة، ويتحقق بعد الفك من UTF-8 ومخطط البرنامج والتعليمات.
الضغط ليس تشفيرًا ولا توقيعًا ولا مصدر ثقة؛ لا تشغّل bytecode غير موثوق
لمجرد أنه مضغوط. اقرأ [حدود الأمان](#17-الأمان-وحدود-الثقة).

المقايضة المقصودة: المستوى `9` يفضل تقليل الحجم على سرعة إنشاء الملف،
والحاوية المضغوطة قد تكون أكبر من JSON إذا كان البرنامج صغيرًا أو غير قابل
للضغط. استخدم JSON عندما تحتاج قراءة بشرية أو ترجمة أسرع، واستخدم الضغط
عندما يكون حجم التخزين أو النقل أهم. لا يجري البرنامج إزالة تعليمات أو
ضغطًا أثناء التنفيذ.

### 15.3 مجموعة التعليمات

| التعليمة | دورها |
|---|---|
| `CONSTANT` | دفع قيمة ثابتة إلى المكدس |
| `LOAD` | تحميل اسم من الإطار أو النطاق العام أو المكتبة |
| `STORE` | تخزين قيمة متغير |
| `STORE_CONST` | تخزين اسم ثابت مرة واحدة |
| `POP` | إسقاط قيمة مؤقتة |
| `DUP` | تكرار قمة المكدس لدعم المنطق القصير |
| `BUILD_LIST` | تجميع عدد من القيم في قائمة |
| `BUILD_MAP` | إنشاء قاموس من أزواج مفتاح وقيمة |
| `INDEX` | فهرسة مجموعة |
| `STORE_INDEX` | تحديث عنصر قائمة أو قاموس |
| `UNARY` | تطبيق `+` أو `-` أو `ليس` |
| `BINARY` | حساب عامل ثنائي أو مقارنة |
| `JUMP` | انتقال مباشر داخل الدالة |
| `JUMP_IF_FALSE` | قفز شرطي مع سحب الشرط |
| `JUMP_IF_TRUE` | قفز شرطي مع سحب الشرط |
| `GET_ITER` | الحصول على مكرر |
| `ITER_NEXT` | جلب العنصر أو القفز عند نهاية التكرار |
| `MAKE_FUNCTION` | إنشاء مرجع إلى دالة مترجمة |
| `CALL` | استدعاء دالة بعدد معاملات معروف |
| `RETURN` | إعادة نتيجة الإطار الحالي |

### 15.4 التحقق وتحسين الثوابت

بعد قراءة bytecode، يتحقق النظام من أسماء التعليمات ومعاملاتها، ثم يحلل
ارتفاع مكدس القيم عبر تعليمات كل دالة. يرفض نقص القيم قبل تنفيذ العملية
والاختلاف في ارتفاع المكدس عند التقاء مسارات القفز، ويتحقق من أن مسار الخروج
العادي لا يترك قيمًا معلقة. هذا فحص لصحة التنسيق وليس بديلًا عن حدود VM أو
ضمانًا لتشغيل ملفات غير موثوقة بأمان.

يطوي المترجم التعبيرات الحسابية التي تتكون من أعداد ثابتة عندما تكون العملية
آمنة والنتيجة ضمن حدود الأعداد. مثلًا تتحول `2 + 3 * 4` إلى ثابت واحد في
bytecode. أما القسمة على صفر أو الأس الكبير أو نتيجة تتجاوز حدود الأعداد
فتبقى عملية تنفيذية، حتى تظهر رسالة الخطأ وقت التشغيل وبالسطر المعتاد.
الطي لا يغيّر ترتيب تقييم تعبيرات تحتوي أسماء أو استدعاءات دوال.

### 15.5 توليد bytecode

تتحول عبارة `إذا` إلى شرط وتعليمة قفز وكتلة أو كتلتين. يحسب المترجم مواضع
القفز بعد ترجمة جسم الكتلة. التحسين الموجود حاليًا محدود بطي الحسابات
الرقمية الثابتة الآمنة؛ لا يوجد حذف للكود الميت أو تحسينات عامة للـVM.

## 16. تصميم المكونات في الشيفرة

### 16.1 `lexer.py`

مسؤولياته:

1. رفض المصادر الأكبر من 1 MiB.
2. تقسيم المصدر إلى أسطر.
3. إصدار `INDENT` و`DEDENT` وفق مستويات المسافة.
4. تمييز الأعداد والنصوص والعوامل والمعرفات.
5. توحيد بعض أشكال كتابة الكلمات العربية.
6. ربط الرمز بسطر وعمود.

لا ينفذ lexer أي كود ولا يحاول تفسير النص العربي كلغة طبيعية. النحو محدد
بكلمات وعوامل معروفة.

### 16.2 `parser.py`

يستخدم محللًا تنازليًا لعبارات المستوى الأعلى والكتل، ومحلل Pratt للتعبيرات.
كل عقدة AST تحمل نوعًا وقيمة وأبناء ورقم سطر. هذا يترك تحديد الدلالات
وتحويل التنفيذ لمرحلة مستقلة.

### 16.3 `compiler.py` و`bytecode.py`

تقدم `compile_source` مدخل المترجم العام: مصدر → رموز → AST → bytecode مع طي
حسابات ثابتة آمنة. يمثل `BytecodeProgram` البرنامج ووحدات الدوال ونقطة
الدخول. `from_json` يرفض صيغة أخرى وأسماء تعليمات غير مدرجة، ويفحص مكدس
كل مسار قابل للوصول. تتعرف `read_bytecode` على JSON القديم والحاوية
المضغوطة؛ وبعد فك الحاوية تمر التعليمات في التحقق نفسه.

### 16.4 `vm.py`

الآلة مكدسية: كل استدعاء دالة يملك مكدس قيم محليًا وإطارًا للأسماء. حدود
التنفيذ والعودية والمجالات تقلل مخاطر الاستهلاك غير المحدود. هذه حدود
تشغيلية وليست sandbox أمنيًا معتمدًا لتشغيل شيفرات عدائية.

### 16.5 `cli.py`

CLI تقرأ UTF-8، تتحقق من قيم الحدود، وتعرض الأخطاء للمستخدم وتعيد رمز خروج
غير صفري عند الفشل. لا تلتقط الأخطاء العامة بصمت.

## 17. الأمان وحدود الثقة

### 17.1 القدرات المتاحة

برنامج سُدى يستطيع الحساب، إنشاء قوائم محلية، استدعاء الدوال المدمجة
المذكورة، والطباعة. لا يستطيع من لغة المصدر وحدها استيراد Python أو تنفيذ
عملية نظام أو فتح socket.

### 17.2 حدود الحماية المنفذة

- حد مصدر 1 MiB.
- حد تعليمات افتراضي مليون تعليمة.
- حد استدعاء افتراضي 128 إطارًا.
- حد `مدى` مئة ألف عنصر.
- حد افتراضي للمخرجات المتراكمة مقداره 1 MiB.
- حد السلاسل UTF-8 المؤقتة 1 MiB، وحد المجموعات والمكدس 100,000 عنصر.
- رفض أعداد صحيحة تتجاوز 4096 بت بعد العملية الحسابية.
- حد الأس 10,000.
- حد نص مطبوع 1 MiB.
- `رتب` و`اعكس` لا تنتجان أكثر من حد عناصر المجموعة المحدد.

هذه ليست ضمانات استهلاك ذاكرة شاملًا: Python نفسها والكائنات الداخلية
تضيف حملًا، وبعض العمليات الكثيفة تستهلك وقتًا قبل التحقق اللاحق. لا تشغل
مدخلات عدائية في عملية لها صلاحيات مهمة. العزل الأقوى يتطلب process
sandbox وقيود نظام التشغيل وحدود وقت/ذاكرة على مستوى المضيف.

### 17.3 bytecode غير موثوق

تنسيقا JSON والحاوية المضغوطة قابلان للاستبدال ولا يحملان توقيعًا رقميًا.
الضغط لا يشفر المحتوى ولا يثبت مصدره. يتحقق القارئ من الحد الأعلى للحجم
المضغوط والمفكوك، وتمام تدفق zlib، وترميز UTF-8 ومخطط JSON ومعاملات
التعليمات؛ لكنه لا يثبت سلامة البرنامج من ناحية السياسة أو صحة منطق العمل.
لا تشغّل bytecode غير موثوق في عملية ذات صلاحيات مهمة. العزل يتطلب process
sandbox وقيود نظام التشغيل وحدود وقت/ذاكرة على مستوى المضيف.

### 17.4 الخصوصية والشبكة

لا تتصل سُدى بالإنترنت ولا ترسل بيانات في هذا الإصدار. لا توجد تحديثات
تلقائية أو خدمات خلفية. السلوك الافتراضي محلي، ويجب أن يظل ذلك موثقًا إذا
أضيفت قدرات مستقبلية.

## 18. الأداء والذاكرة: ما يمكن قوله بأمان

البرنامج يترجم إلى bytecode ثم ينفذ بواسطة حلقات Python، ولذلك لا يتوقع أن
يتفوق على تنفيذ Python المباشر أو على Rust/C. التحويل إلى bytecode يخدم
تجربة بنية مترجم صغيرة وسلوكًا متكررًا قابلًا للاختبار، لا تسريعًا مضمونًا.

لإجراء مقارنة عادلة مستقبلًا:

1. نفّذ الخوارزمية نفسها في سُدى وPython وRust.
2. استخدم إدخالًا ومخرجات متطابقة.
3. استبعد زمن بدء المترجم أو أدرجه منفصلًا بوضوح.
4. نفذ إحماءً وكرر القياس.
5. سجل وسيط الزمن وتوزعه وذروة الذاكرة وإصدار الأدوات والجهاز.
6. تحقق من صحة النتيجة قبل مقارنة الزمن.

يعرض benchmark الحالي أيضًا حجم JSON وحاوية zlib لبرنامج الحلقة نفسه،
والبايتات الموفرة، والزمن الوسيط للضغط وفك الضغط. عدد الجولات نفسه يستخدم
لأزمنة المقارنة. انتبه إلى أن برنامج الحلقة صغير جدًا، لذا قد لا يكون حجمه
ممثلًا لبرامج كبيرة، وأن نسبة التوفير تختلف باختلاف النص والبيانات.

يوفر الإصدار ضغط zlib اختياريًا لملفات bytecode فقط؛ لا يضغط أوزان نماذج
الذكاء الاصطناعي. لا يوجد تكميم (quantization) أو runtime ذكاء اصطناعي.
هذه مسائل مختلفة تتطلب صيغ بيانات واختبارات دقة وأحمالًا مرجعية منفصلة.

اختبر الضغط على الملف الفعلي: الصيغ النصية المتكررة غالبًا تنضغط جيدًا،
أما الملف الصغير أو المحتوى عالي العشوائية فقد لا يصغر وقد يكبر بسبب ترويسة
الحاوية. الضغط يقلل التخزين والنقل ولا يسرّع VM، كما أن المستوى 9 يزيد
كلفة إنشاء الملف. أداة `benchmarks/benchmark.py` تطبع الحجم قبل الضغط وبعده
ونسبة التوفير والزمن الوسيط للضغط وفكّه للبرنامج الذي قاست تنفيذه. النتيجة
خاصة بذلك البرنامج والجهاز وليست وعدًا عامًا بنسبة توفير أو بسرعة معينة.

## 19. أمثلة كاملة

### 19.1 مجموع مجال

```text
دالة مجموع_حتى(ن):
    إجمالي = 0
    لكل عنصر في مدى(1, ن + 1):
        إجمالي = إجمالي + عنصر
    أرجع إجمالي

اطبع(مجموع_حتى(10))
```

### 19.2 ترتيب قائمة باستخدام المكتبة القياسية

```text
قيم = [5, 2, 4, 1]
مرتبة = رتب(قيم)
اطبع(مرتبة)
اطبع(اعكس(مرتبة))
اطبع(قيم)
```

الناتج:

```text
[1, 2, 4, 5]
[5, 4, 2, 1]
[5, 2, 4, 1]
```

يعيد `رتب` و`اعكس` قائمتين جديدتين؛ تبقى القائمة الأصلية كما هي. يحافظ
`رتب` على ترتيب العناصر المتساوية (فرز مستقر). القيم المختلفة الأنواع التي
لا يمكن مقارنتها تسبب خطأ وقت التشغيل، لا ترتيبًا اعتباطيًا.

### 19.3 فرز فقاعي تعليمي لقائمة

```text
قيم = [5, 2, 4, 1]
نهاية = طول(قيم)
طالما نهاية > 1:
    موضع = 0
    طالما موضع < نهاية - 1:
        إذا قيم[موضع] > قيم[موضع + 1]:
            مؤقت = قيم[موضع]
            قيم[موضع] = قيم[موضع + 1]
            قيم[موضع + 1] = مؤقت
        موضع = موضع + 1
    نهاية = نهاية - 1
اطبع(قيم)
```

الناتج:

```text
[1, 2, 4, 5]
```

هذا المثال توضيحي وتعقيده الزمني تربيعي؛ القوائم الكبيرة ستصطدم بحد
التعليمات أسرع من خوارزمية فرز مدمجة (غير موجودة في الإصدار الحالي).

### 19.4 حساب عاملي تكراري

```text
دالة عاملي(ن):
    إذا ن <= 1:
        أرجع 1
    أرجع ن * عاملي(ن - 1)

اطبع(عاملي(6))
```

### 19.5 كشف الأعداد الزوجية

```text
لكل عدد في مدى(10):
    إذا عدد % 2 == 0:
        اطبع(عدد, "زوجي")
    وإلا:
        اطبع(عدد, "فردي")
```

### 19.6 قائمة ومؤشر

```text
ألوان = ["أحمر", "أخضر", "أزرق"]
اطبع("عدد الألوان:", طول(ألوان))
```

## 21. قرارات التصميم المؤقتة التي تحتاج مواصفة

- هل تكون الأسماء حساسة للتشكيل؟ التنفيذ الحالي يطابق النص بعد NFC فقط.
- ما القيم التي تعد صحيحة في الشرط؟ التنفيذ الحالي يتبع truthiness في Python.
- هل تنفذ القسمة `/` بدقة عائمة دائمًا؟ التنفيذ الحالي يستعمل `truediv`.
- هل يسمح بخلط النص والرقم في `+`؟ التنفيذ يترك قرار النوع للآلة.
- هل الأرقام الصحيحة 64 بت أم غير محدودة؟ التنفيذ الحالي يقيد النتائج عند 4096 بت.
- ما مدى توافق backend مع Unicode؟ يلزم اختبار مستقل لكل هدف.
- كيف تدار الحزم والإصدارات؟ لم يضف مدير حزم حتى الآن.

يجب حسم هذه القرارات في مواصفة معيارية واختبارات مطابقة قبل إعلان الاستقرار.

## 22. النحو المرجعي (EBNF تقريبي)

القواعد التالية تلخص نحو الإصدار 0.5.0. يصدر المحلل المعجمي الرموز
`INDENT` و`DEDENT` و`NEWLINE`؛ كما أن الأسماء المحجوزة والاختصارات الدقيقة
تُحسم في المنفذ الفعلي في `src/suda/lexer.py` و`src/suda/parser.py`.
لذلك هذه صياغة مرجعية مبسطة، وليست بديلًا عن اختبارات النحو.

```ebnf
program              = { NEWLINE | statement }, EOF ;
statement            = assignment | constant_declaration
                     | function_declaration | if_statement
                     | while_statement | for_statement
                     | loop_control | return_statement
                     | expression_statement ;
assignment           = ( IDENT | indexed_target ), "=", expression, NEWLINE ;
indexed_target       = primary, index_suffix, { index_suffix } ;
constant_declaration = "ثابت", IDENT, "=", expression, NEWLINE ;
function_declaration = "دالة", IDENT, "(", [ parameters ], ")", ":", block ;
parameters           = IDENT, { ",", IDENT }, [ "," ] ;
return_statement     = "أرجع", expression, NEWLINE ;
expression_statement = expression, NEWLINE ;
if_statement         = "إذا", expression, ":", block,
                       [ "وإلا", ( if_statement | ":", block ) ] ;
while_statement      = "طالما", expression, ":", block ;
for_statement        = "لكل", IDENT, "في", expression, ":", block ;
loop_control         = ("اكسر" | "استمر"), NEWLINE ;
block                = NEWLINE, INDENT, { statement | NEWLINE }, DEDENT ;
expression           = disjunction ;
disjunction          = conjunction, { "أو", conjunction } ;
conjunction          = comparison, { "و", comparison } ;
comparison           = sum, [ ("==" | "!=" | "<" | "<=" | ">" | ">="), sum ] ;
sum                  = product, { ("+" | "-"), product } ;
product              = power, { ("*" | "/" | "//" | "%"), power } ;
power                = unary, [ "**", power ] ;
unary                = ("+" | "-" | "ليس"), unary | postfix ;
postfix              = primary, { call_suffix | index_suffix } ;
call_suffix          = "(", [ expression, { ",", expression }, [ "," ] ], ")" ;
index_suffix         = "[", expression, "]" ;
primary              = NUMBER | STRING | "صحيح" | "خطأ" | "لا_شيء"
                     | IDENT | "(", expression, ")"
                     | "[", [ expression, { ",", expression }, [ "," ] ], "]"
                     | "{", [ expression, ":", expression,
                               { ",", expression, ":", expression },
                               [ "," ] ], "}" ;
```

## 23. الحالة وما التالي؟

### المنفذ والمختبر في 0.5.0

- التحليل العربي/الإنجليزي، الكتل، القيم، الدوال، التحكم والحلقات.
- القوائم والقواميس وفهرستها، مع حدود للعناصر.
- مكتبة قياسية تشمل الطباعة والتحويلات والمدى والمجاميع و`رتب` و`اعكس`.
- bytecode إصدار 1 بصيغة JSON، وضغط zlib اختياري متوافق مع الصيغة القديمة.
- طي حسابات رقمية ثابتة آمنة، وفحص تدفق المكدس ومسارات القفز في bytecode.
- واجهة أوامر، دليل كامل، أمثلة واختبارات آلية.

### غير منفذ؛ لا تعتبره ميزة مدعومة

- backend إلى كود آلة أصلي أو وعد بتجاوز سرعة Python.
- نظام أنواع ساكن أو ملكية/استعارة.
- وحدات وحزم وإدارة تبعيات.
- واجهات رسومية أو مولدات Android/iOS/Web/Desktop.
- شبكة أو قواعد بيانات أو تشغيل أوامر نظام من لغة المصدر.
- runtime ذكاء اصطناعي أو دعم ONNX/llama.cpp أو ضغط أوزان النماذج.
- توقيع bytecode أو sandbox معتمد لتشغيل ملفات عدائية.
- formatter أو LSP أو debugger أو profiler مدمج.

### أولويات التطوير المقترحة

1. توحيد دلالات الأنواع وtruthiness وإكمال اختبارات المطابقة.
2. إضافة فاحص أنواع اختياري مع توثيق قواعده.
3. مكتبة قياسية محدودة مع صلاحيات واضحة واختبارات الموارد.
4. وحدات محلية بإصدارات ثابتة وتجزئات تحقق.
5. تثبيت تنسيق bytecode الثنائي واختبارات توافق بين المنصات والإصدارات.
6. تجربة backend فعلي عبر LLVM أو C، ثم قياس الأداء قبل ادعاء السرعة.
7. WebAssembly أو أهداف الهاتف بعد وجود أدوات بناء وruntime واختبارات تكامل.
8. دمج AI عبر واجهة مستقلة ومعايير صحة/ذاكرة/زمن حقيقية.

لا يعد الهدف مدعومًا لمجرد توليد ملف له؛ يتطلب backend/runtime متكاملًا،
واختبارات بناء وتشغيل قابلة للإعادة، ووثائق وقياسات على الهدف نفسه.

## 24. قائمة مرجعية لمؤلف برنامج سُدى

قبل تشغيل برنامج تجريبي:

1. احفظ الملف بترميز UTF-8.
2. اكتب الكلمات المحجوزة كما يحددها النحو ولا تعتمد على فهم اللغة الطبيعية.
3. استخدم أربع مسافات لكل مستوى كتلة.
4. أعطِ المتغيرات والدوال أسماء دالة على معناها.
5. لا تنشئ حلقة بلا شرط خروج.
6. ضع حدًا صريحًا على المجال الذي يمرره البرنامج إلى `مدى`.
7. تحقق من الفهارس قبل استخدام قائمة أو سلسلة.
8. توقع أن ينتج الحساب غير الصالح خطأ، ولا تعتمد على إصلاح تلقائي.
9. لا تشغل ملفات bytecode جاءت من مصدر غير معروف.
10. اختبر مثالًا صغيرًا قبل الملف الكبير، ثم شغّل مجموعة الاختبارات.

## 25. أسئلة تشغيل متكررة

### لماذا لا يعمل أمر `suda` بعد تثبيت المصدر؟

قد تكون حزمة Scripts غير موجودة في `PATH`. جرّب `python -m suda` من جذر
المشروع أو أعد تثبيت الحزمة داخل البيئة الافتراضية التي ستستخدمها.

### لماذا لا يظهر العربي بصورة سليمة في الطرفية؟

تأكد من ترميز الملف UTF-8 واستخدم طرفية تدعم Unicode. قد تعرض بعض إعدادات
Windows القديمة رموزًا مشوهة رغم أن bytes الملف صحيحة. لا تعالج المشكلة
باستبدال الحروف العربية بأسماء إنجليزية في المصدر إلا كاختبار تشخيصي.

### لماذا يطبع `نوع(صحيح)` اسمًا داخليًا؟

`نوع` أداة تشخيص مؤقتة وتعكس اسم نوع Python المضيف؛ لا تعتمد عليها كواجهة
توافق بين نسخ اللغة. عند إضافة نظام أنواع، ستحدد اللغة أسماء معيارية خاصة
بها.

### لماذا لا يمكن الوصول إلى `قائمة[0] = قيمة`؟

إسناد الهدف المركب يقبل اسمًا أو فهرسًا واحدًا في قائمة أو قاموس، ولا يقبل
التقطيع. الفهارس السالبة للقوائم تتبع Python. العناصر داخل القوائم
والقواميس القابلة للتعديل يمكن تعديلها حتى لو كان اسم المرجع ثابتًا.

### هل `check` يشغّل البرنامج؟

لا. الأمر يترجم المصدر فقط، ولا يستدعي الآلة الافتراضية. أخطاء التشغيل
تكتشفها `run` أو اختبارات البرنامج.

### هل يمكن تشغيل AI أو موقع أو تطبيق جوال؟

ليس بهذا الإصدار. توجد رؤية وخارطة طريق، لكن لا توجد مكتبات المنصات أو
مترجمات هذه الأهداف. لا يترجم المثال الذي يذكر هدفًا غير مدعوم إلى تطبيق.
